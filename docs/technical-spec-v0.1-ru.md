# Smart Ducking VST3

> Актуализация для 1.0.0: этот файл сохраняет исходную структуру v0.1, но выполненные разделы приведены к фактическому release-поведению. Один `Smart Ducking.vst3` регистрирует два класса — `Smart Ducking (Stereo)` с шинами `2 + 6 + 2` и `Smart Ducking (Surround)` с шинами `6 + 6 + 6`. Main задаётся классом; Voice выбирается как Stereo/Surround и всегда поступает по физической 5.1-шине. DSP-код обоих классов общий.

## Техническая спецификация v0.1

**Статус:** исходная спецификация для DSP-прототипа
**Дата:** 6 августа 2026
**Целевая задача:** сведение закадровой озвучки с оригинальной стереофонической фонограммой

## 1. Назначение

Плагин автоматически освобождает для закадрового голоса спектральное и пространственное место в оригинальной фонограмме. В отличие от простого широкополосного sidechain-компрессора он:

1. сохраняет низкочастотную полосу оригинала;
2. преобразует стереофонический материал во внутреннее LCR-представление;
3. выполняет поканальный широкополосный дакинг с контролируемым влиянием на соседние каналы;
4. во время речи подавляет выступающие спектральные компоненты оригинала;
5. при тишине в sidechain приостанавливает ресурсоёмкую обработку без изменения задержки и без слышимых переключений.

## 2. Термины

- **Оригинал / равка / Main** — исходная фонограмма фильма, сериала или иного материала.
- **Голос / Sidechain** — предварительно смикшированная и очищенная шина голосов озвучки. На слышимый выход плагина она не поступает.
- **LCR** — внутренние каналы Left, Center, Right.
- **PCE** — Phantom Center Extraction: выделение фантомного центра из stereo с сохранением боковых составляющих.
- **Wideband ducking** — широкополосное ослабление соответствующего канала оригинала.
- **Spectral suppression** — динамическое подавление выступающих компонентов спектра оригинала во время активности голоса.
- **Technical silence** — практически нулевой сигнал, используемый для классификации каналов, а не для определения наличия речи.

## 3. Целевая платформа первой версии

- ОС: Windows и macOS.
- Основной хост: REAPER.
- Формат: VST3; Standalone собирается как вспомогательный target.
- Main: fixed Stereo или 5.1 по выбранному plugin class.
- Voice Sidechain: физически 5.1 с интерпретацией Stereo или Surround.
- Внутренние spatial channels: L/C/R для Stereo, L/C/R/Ls/Rs для Surround; LFE исключён из detection/reduction.
- Реализация: C++20 и JUCE 8.0.12 с общим DSP-ядром для обоих VST3 classes.

## 5. Обработка оригинала

### 5.1 Кроссовер

- Тип: minimum-phase Linkwitz–Riley 8-го порядка.
- Крутизна: 48 dB/oct.
- Частота по умолчанию: 92 Hz.
- Пользовательский диапазон: 50–180 Hz.
- Низкая полоса остаётся в исходном stereo и не подвергается PCE, широкополосному дакингу или спектральному подавлению.
- Низкая полоса задерживается до точного временного совпадения с обработанной верхней ветвью.

Сумма minimum-phase полос может иметь ровную амплитудную характеристику, но отличаться от исходника фазовым вращением. Поэтому отсутствие полного null с необработанным оригиналом не является ошибкой и не используется как единственный критерий корректности.

### 5.2 Phantom Center Extraction оригинала

PCE оригинала работает перед спектральным подавлением stereo-верхней полосы. Контент-зависимые быстрые пути для mono, dual mono и одностороннего сигнала на Main не используются: динамическое переключение внутреннего пространственного представления может менять характер обработки и создавать артефакты.

В v0.1 параметры PCE фиксированы и не выводятся в интерфейс.

Выбранная реализация использует тот же STFT, что и спектральное подавление: из L/R сначала рассчитываются внутренние L/C/R, после чего независимые spectral masks применяются к трём компонентам до inverse FFT. Фактор выделения центра адаптирован из Apache-2.0 проекта `willleskowitz/upmix`, но вместо вырожденной покадровой оценки используется временно сглаженный комплексный cross-spectrum.

Внутренняя нормировка и обратное преобразование:

```text
common = 0.5 × centreFactor × (L + R)
LcrL = L - common
LcrC = sqrt(2) × common
LcrR = R - common

stereoL = LcrL + LcrC / sqrt(2)
stereoR = LcrR + LcrC / sqrt(2)
```

До применения независимых LCR-gain это тождественная реконструкция для любого `centreFactor`.

Требуемые свойства:

- равные синфазные L/R преимущественно переходят в C;
- жёстко панорамированный сигнал остаётся на своей стороне и не должен заметно протекать в C или противоположную сторону;
- боковые остатки не должны приобретать выраженную отрицательную корреляцию, характерную для простого Mid/Side-разложения;
- преобразование `Stereo → LCR → Stereo` без дакинга должно быть максимально прозрачным по уровню, панораме и тембру;
- точные нормировки и математический метод выбираются по результатам DSP-прототипа и прослушивания.

Референс по ожидаемому поведению: [Bertom Phantom Center](https://bertomaudio.com/phantom-center.html). Реализация не предполагает копирования закрытого алгоритма.

## 6. Обработка sidechain

### 6.1 Классификация stereo

Оптимизация классификации применяется только к sidechain.

| Определённый режим | Внутренняя маршрутизация |
|---|---|
| Silence | L = 0, C = 0, R = 0 |
| Left only | L = input L, C = 0, R = 0 |
| Right only | L = 0, C = 0, R = input R |
| Dual mono | L = 0, C = mono, R = 0 |
| True stereo | Phantom Center Extraction → LCR |

Для определения dual mono недостаточно одного коэффициента корреляции: корреляция может быть равна 1 при разных уровнях каналов. Основная проверка:

```text
dualMonoDifference = energy(L − R) / (energy(L) + energy(R) + epsilon)
```

Дополнительно проверяются:

- близость уровней L/R;
- положительная корреляция;
- устойчивость результата на протяжении окна классификации.

Классификатор анализирует текущее перекрывающееся FFT-окно. Реализованные критерии:

- техническая тишина канала: peak не выше `1e-8`;
- dual-mono difference не выше `1e-6`;
- относительный дисбаланс уровней не выше `0.002`;
- положительная корреляция не ниже `0.9999`.

После тишины определённый маршрут включается сразу, чтобы не пропустить начало первой фонемы. Вход из stereo в быстрый маршрут требует 100 ms стабильности. Выход в stereo происходит немедленно; переход между двумя различными быстрыми маршрутами сначала проходит через безопасный stereo-режим. Дополнительный crossfade управляющего сигнала не применяется: быстрые маршруты сохраняют нормировку существующего FFT-детектора, а дальнейшее изменение gain сглаживает общая Attack/Hold/Release-огибающая.

В режимах Left only, Right only и Dual mono выполняется один Voice forward FFT вместо двух, а Voice PCE обходится. В Stereo выполняются два Voice forward FFT и PCE. Для Dual mono детектор C получает энергонормированный коэффициент `1 / centreDownmixGain = sqrt(2)`, поэтому смена маршрута не меняет его шкалу.

### 6.2 Mono sidechain

Если хост предоставит настоящий mono sidechain, он направляется только во внутренний канал C.

В типичной конфигурации REAPER mono-шина, продублированная в равные L/R, будет определена как dual mono и также направлена только в C.

### 6.3 Техническая тишина и активность голоса

Используются два независимых понятия:

```text
Technical silence: ориентировочно −100…−120 dBFS
Detector floor:    −60 dBFS, fixed
Voice Full:        −30 dBFS, adjustable
```

- Technical silence используется для определения пустых каналов и быстрых маршрутов.
- Voice activity используется для управления дакингом и состоянием ресурсоёмких алгоритмов.
- Нижняя граница детектора фиксирована на −60 dBFS.
- Верхняя граница Voice Full регулируется от −60 до 0 dBFS, default −30 dBFS.
- Уровень измеряется после PCE соответствующего канала.
- Ниже −60 dBFS управляющий сигнал равен 0, между границами линейно растёт в dB-шкале, выше Voice Full равен 1.
- Короткие звуки не отбрасываются: щелчок языком и иные артикуляционные элементы должны активировать обработку.
- Специальный de-click или минимальная длительность события в v0.1 не применяются.

### 6.4 Выравнивание управляющего сигнала

Sidechain является очищенной и заранее смикшированной шиной голосов. Сначала выполняется PCE, затем уровень каждого L/C/R-компонента независимо переводится в управляющее значение от 0 до 1. Нижняя точка фиксирована на −60 dBFS, верхняя задаётся Voice Full. Интерполяция между ними линейна в dB-шкале и непрерывна на обеих границах. После level mapping применяются Attack/Hold/Release. Полученные L/C/R-огибающие совместно управляют спектральным и широкополосным дакингом.

Параметры по умолчанию:

- detector floor: −60 dBFS, fixed;
- Voice Full: −30 dBFS;
- attack: 50 ms;
- hold: 150 ms;
- release: 200 ms.

Старый Sidechain Pre-Gain удалён из host parameters и DSP. При загрузке старого состояния legacy child безопасно удаляется миграцией, остальные параметры сохраняются.

## 7. Широкополосный дакинг

### 7.1 Семантика матрицы

Строка матрицы обозначает канал детектора голоса, столбец — обрабатываемый канал оригинала. Значение от 0 до 1 умножает максимальную глубину дакинга в dB.

```text
channelDuck[j] = max(sidechainEnvelope[i] × matrix[i][j])
gainReductionDb[j] = duckDepthDb × channelDuck[j]
```

Для одновременной активности нескольких голосовых каналов используется `maximum`, а не сумма. Воздействие не превышает 100% установленной глубины.

### 7.2 Стартовая LCR-матрица

| Голос ↓ / оригинал → | L | C | R |
|---|---:|---:|---:|
| L | 1.00 | 0.25 | 0.00 |
| C | 0.10 | 1.00 | 0.10 |
| R | 0.00 | 0.25 | 1.00 |

### 7.3 Стартовая 5.1-матрица для будущей версии

| Голос ↓ / оригинал → | L | C | R | Ls | Rs |
|---|---:|---:|---:|---:|---:|
| L  | 1.00 | 0.25 | 0.00 | 0.35 | 0.00 |
| C  | 0.10 | 1.00 | 0.10 | 0.05 | 0.05 |
| R  | 0.00 | 0.25 | 1.00 | 0.00 | 0.35 |
| Ls | 0.35 | 0.00 | 0.00 | 1.00 | 0.05 |
| Rs | 0.00 | 0.00 | 0.35 | 0.05 | 1.00 |

LFE исключается из детектирования и обработки.

### 7.4 Параметры

- Duck Depth по умолчанию: 15 dB.
- Регулируемый диапазон: 0–18 dB.
- Все ячейки матрицы должны быть регулируемыми в диапазоне 0–100%.
- Дакинг применяется только к верхней LCR-ветви оригинала.

## 8. Спектральное подавление

### 8.1 Выбранный принцип

Используется вариант A: голос только разрешает и масштабирует подавление, а частоты для подавления определяются исключительно анализом оригинала.

```text
spectralReduction =
    originalSpectralProminence
  × correspondingLcrSidechainEnvelope
  × weightingBell
  × spectralAmount
```

Спектр голоса не анализируется. Voice-matched spectral ducking и гибридный алгоритм в v0.1 не реализуются, поскольку в контексте закадровой озвучки они могут звучать неестественно.

### 8.2 Пространственная связь

Спектральное подавление действует только на соответствующую внутреннюю L/C/R-компоненту:

```text
Voice L → Original L
Voice C → Original C
Voice R → Original R
```

Mono или dual-mono sidechain преимущественно переходит в C. Спектральная обработка выполняется после кроссовера и PCE. Матрица соседства используется только широкополосным LCR-дакингом: спектральное подавление остаётся строго прямым и не влияет на соседние LCR-компоненты. Отдельная спектральная матрица не планируется.

### 8.3 Диапазон и weighting

- Рабочий диапазон по умолчанию: 150 Hz – 20 kHz.
- Нижняя и верхняя границы регулируемые.
- Weighting EQ: один широкий bell.
- Частота bell по умолчанию: 3 kHz.
- Gain по умолчанию: +6 dB.
- Q по умолчанию: 0.8.
- Frequency, Gain и Q регулируемые.
- Weighting меняет чувствительность спектрального детектора и не эквализирует слышимый голос или оригинал.
- Spectral Amount по умолчанию: 10 dB.
- Диапазон Spectral Amount: 0–18 dB.
- Общий лимит суммы wideband и spectral reduction не применяется.

### 8.4 Детектор спектральной выраженности

Точный способ определения `originalSpectralProminence` является задачей DSP-прототипа. Требования к результату:

- подавлять локально выступающие компоненты оригинала, а не равномерно опускать весь диапазон;
- избегать быстро дрожащей спектральной маски;
- сглаживать маску по частоте и времени;
- сохранять естественные транзиенты настолько, насколько это совместимо с освобождением места для голоса;
- не анализировать sidechain FFT;
- полностью обходить тяжёлую спектральную ветвь при Spectral Amount = 0.

Временное сглаживание стабилизирует только нормализованную форму спектральной маски, рассчитанную по оригиналу. Глубина этой маски умножается на общую L/C/R Attack/Hold/Release-огибающую уже после сглаживания формы. Отдельные spectral attack/release не применяются; поэтому каскадного замедления реакции нет. При пробуждении тяжёлой ветви форма маски инициализируется сразу.

Анализ выраженности выполняется на сигнале оригинала до применения широкополосного дакинга. После формирования спектральной маски применяются spectral gain и затем wideband gain.

## 9. FFT Resolution

Пользовательский параметр называется `FFT Resolution`, поскольку более длинное окно означает иной компромисс между частотным и временным разрешением, а не безусловно более высокое качество.

### 9.1 При 44.1/48 kHz

| Режим | FFT size | Приблизительная длина при 48 kHz | Разрешение при 48 kHz |
|---|---:|---:|---:|
| ×1 Fast | 1024 | 21.3 ms | 46.9 Hz |
| ×2 Normal | 2048 | 42.7 ms | 23.4 Hz |
| ×4 Fine | 4096 | 85.3 ms | 11.7 Hz |

Default: `×2 Normal`.

### 9.2 При 88.2/96 kHz

Для приблизительного сохранения временного и частотного характера размеры удваиваются:

| Режим | FFT size |
|---|---:|
| ×1 Fast | 2048 |
| ×2 Normal | 4096 |
| ×4 Fine | 8192 |

### 9.3 Overlap и окно

- Исходная гипотеза: 4× overlap, hop size = FFT size / 4.
- Анализирующее и синтезирующее окна должны обеспечивать стабильную perfect-reconstruction overlap-add при unity gain.
- Окончательные window и overlap выбираются после сравнительного теста 2× и 4× по артефактам и CPU.
- Изменение FFT Resolution переключает заранее выделенную geometry, сбрасывает STFT state и меняет заявленную задержку.
- FFT Resolution не применяется во время воспроизведения: новое значение остаётся pending до остановки transport или следующего `prepareToPlay`. Если DAW после Stop прекращает `processBlock()` до передачи stopped state, четыре неизменившихся тика таймера 20 Hz (около 200 ms без аудиоколбэков) считаются безопасным признаком остановки.

Задержка 8192 samples у стороннего референсного плагина не принимается как требование: она может включать не только размер FFT, но и lookahead, накопление кадров и иные внутренние стадии.

## 10. Lookahead и задержка

- Lookahead регулируется от 0 до 50 ms.
- Default: 10 ms.
- Main всегда резервирует 50 ms задержки, а Voice задерживается на `50 ms − Lookahead`.
- Общая заявленная задержка равна алгоритмической задержке STFT плюс фиксированные 50 ms.
- Плагин сообщает задержку хосту для PDC.
- Плагин сообщает конечный tail 2.0 s для дренирования delayed STFT, crossover и overlap-add после тишины на входе.
- Задержка одинакова в состояниях SLEEP, WAKING, ACTIVE и TAIL.
- Низкая полоса и dry-пути задерживаются до совпадения с обработанной ветвью.
- Изменение Lookahead не меняет PDC; sidechain delay tap перемещается со сглаживанием.
- FFT Resolution применяется безопасно при остановленном transport или следующем `prepareToPlay`, после чего host получает обновлённую PDC.
- Внутренний sleep никогда не должен менять PDC.

## 11. Оптимизация при тишине sidechain

Используется машина состояний:

```text
SLEEP → WAKING → ACTIVE → TAIL → SLEEP
```

### 11.1 SLEEP

Продолжают работать:

- дешёвый sidechain activity detector;
- кроссовер и его состояния;
- кольцевые буферы истории и фиксированной задержки;
- синхронизация main/sidechain;
- необходимые envelope followers.

Приостанавливаются:

- FFT-анализ оригинала;
- PCE оригинала и Voice;
- расчёт спектральной gain mask;
- inverse FFT и spectral overlap-add, если архитектура позволяет безопасно перейти на выровненный dry-путь.

Выход продолжает идти через фазово и временно согласованный путь с неизменной задержкой.

### 11.2 WAKING

- При обнаружении голоса спектральная ветвь получает pre-roll из кольцевого буфера оригинала.
- Размер хранимой истории должен покрывать как минимум необходимое FFT-окно и lookahead.
- До момента слышимого воздействия алгоритм должен иметь валидные overlap-add данные.
- Переход к обработанной ветви выполняется без щелчка; attack и при необходимости короткий crossfade маскируют запуск.

### 11.3 ACTIVE

- Wideband и spectral processing работают штатно.
- Спектральная ветвь может активироваться независимо для L, C и R в соответствии с прямым sidechain-детектором.
- Соседний wideband duck продолжает рассчитываться даже тогда, когда спектральная ветвь данного соседнего канала спит.

### 11.4 TAIL

После исчезновения sidechain тяжёлая обработка продолжается до завершения:

- hold;
- release;
- очистки overlap-add хвоста;
- дополнительного защитного интервала, предварительно 50 ms.

При defaults ожидаемое время до сна составляет ориентировочно 400 ms после последнего активного сигнала.

## 13. Требования реального времени

- Никаких выделений памяти, блокировок, файлового ввода-вывода или непредсказуемых системных вызовов в audio thread.
- Корректная работа с переменным размером блока REAPER.
- Отсутствие denormal slowdown на затухающих состояниях фильтров и envelopes.
- Детерминированное поведение при realtime playback и offline render.
- Все внутренние буферы выделяются при prepare/reset или при безопасном изменении конфигурации.
- При смене sample rate, FFT Resolution или channel layout состояния корректно пересоздаются.
- При bypass отдельных DSP-стадий и Global Bypass сохраняются заявленная задержка и временное выравнивание.
- Использование SIMD и иных оптимизаций рассматривается после профилирования, а не вместо него.

## 14. Проверка и критерии приёмки DSP-прототипа

### 14.1 Кроссовер

- Ровная амплитуда суммы полос без провала или подъёма около crossover.
- Отсутствие слышимого изменения тембра при отсутствии дакинга.
- Стабильная импульсная характеристика.
- Null с исходником не обязателен из-за фазового вращения minimum-phase crossover.

### 14.2 PCE

- Dual mono преимущественно попадает в C.
- Hard-left не протекает заметно в C/R; hard-right — в C/L.
- Необработанный round trip сохраняет уровень, панораму и тембр.
- Переходы классификатора sidechain не вызывают скачков управляющих envelopes.

### 14.3 Матрица

- При Voice C = 100% получаем C = 100%, L/R = 10% установленной глубины.
- При Voice L = 100% получаем L = 100%, C = 25%, R = 0%.
- Несколько активных voice-каналов объединяются через maximum и не превышают 100%.
- Изменения матрицы сглаживаются.

### 14.4 Спектральная обработка

- Работает только при прямой активности соответствующего voice-канала.
- Не следует спектру голоса.
- Предпочтительно подавляет выраженные компоненты оригинала.
- Не создаёт заметного musical noise, дрожания спектра или щелчков.
- При Spectral Amount = 0 тяжёлая ветвь не расходует CPU.
- Сравниваются ×1, ×2 и ×4 на речи, музыке, эффектах и сложном полном миксе.

### 14.5 Sleep/wake

- Задержка и PDC не меняются.
- Начало первой фонемы не проходит без требуемой обработки.
- Нет щелчков при SLEEP ↔ ACTIVE.
- Хвост release не обрывается.
- Длительные сцены без речи дают измеримое снижение CPU.
- Результат offline render детерминирован и совпадает с realtime в пределах численной точности.

## 15. Диагностические функции

Текущий resizable editor постоянно отображает Main/Voice/Output meters и независимые wideband/spectral gain-reduction meters. Две прямые страницы `DYNAMICS` и `ROUTING` заменяют старую иерархию Simple/Advanced/Spectrum. Crossover, Spectral Low и Spectral High редактируются маркерами анализатора; Dynamics также содержит Lookahead, FFT Resolution и `QUALITY / NORMAL`. Matrix использует линейные процентные слайдеры, общие заголовки строк/столбцов и динамические размеры 3×3, 3×5, 5×3 или 5×5.

Weight Frequency/Gain/Q редактируются одной parametric node: drag меняет frequency/gain, Shift-drag или wheel меняет Q, double-click возвращает defaults. `L/R LINK` — только инструмент ручного редактирования и не зеркалит host automation.

В единой группе стадий bypass обозначен векторной иконкой. Crossover предлагает `Bypass / LOW / HIGH`; обе monitor-полосы комплементарны и исключают LFE. Wideband и Spectral предлагают `Bypass / S / Δ`, причём Delta возвращает удалённый сигнал своей стадии. Monitor Mode взаимо исключает режимы прослушивания. Рядом с фактическим индикатором heavy engine `SLEEP / ACTIVE` находится отдельный Global Bypass: стандартный VST3-параметр плавно переключает на raw Main, выровненный по полной PDC, и обходит также remapping/downmix/Drop LFE.

Кнопки `A / B` хранят два parameter snapshot в project state, не меняя Global Bypass. Host program list содержит `Default`, `Gentle Dialogue`, `Voice Focus` и `Fast Announcer`. Выбранная Dynamics/Routing page и matrix-link также сохраняются.

DiagnosticLogger в diagnostic build публикует lock-free counters и записывает snapshot отдельным low-priority thread раз в 1000 ms. Production build отключает файловую диагностику; audio callback не выполняет I/O и блокировки.

## 19. Краткое определение v0.1

Первая версия — это один Windows VST3-бандл для REAPER с двумя классами: Stereo 2+6+2 и Surround 6+6+6. Оба используют общий DSP; Main задаётся классом, а Voice вручную выбирается как Stereo или Surround. Низ оригинала ниже регулируемого crossover сохраняется отдельно. Stereo-верхняя полоса переводится в LCR, а Surround обрабатывается как L/C/R/Ls/Rs; далее выполняются прямое спектральное подавление варианта A и матричный широкополосный дакинг. FFT имеет три разрешения, по умолчанию 2048 samples при 48 kHz. При отсутствии голоса тяжёлая спектральная обработка засыпает, но задержка, PDC и звуковой путь остаются неизменными.
